# TCPSnitch

`tcpsnitch` is a network tracing tool designed to investigate the interactions between an application and the TCP/IP stack. It works by intercepting `libc` function calls on internet sockets (via `LD_PRELOAD`) and, optionally on Linux, by capturing low-level kernel events using modern **eBPF (Extended Berkeley Packet Filter)** technologies.

## Overview

To start gently, one may run the following command to trace the `curl` program:
```bash
$ tcpsnitch curl google.com
[tcpsnitch] Trace saved in: /tmp/tcpsnitch_output/curl_20260318_112005
```

For each event, `tcpsnitch` records the arguments, the return value, and various metadata such as the current timestamp, thread ID, and execution context. Specifically, a non-blocking `connect()` event might look like this in a socket trace:

```JSON
{
    "type": "connect",
    "timestamp_usec": 1773829205275179,
    "return_value": -1,
    "success": false,
    "errno": "EINPROGRESS",
    "thread_id": 280169,
    "fake_call": false,
    "repeat_count": 1,
    "details": {
        "addr": {
            "sa_family": "AF_INET",
            "ip": "64.233.184.102",
            "port": "80"
        }
    }
}
```

*Note: The `fake_call` boolean indicates whether the event was artificially generated by `tcpsnitch` (e.g., periodic `TCP_INFO` polling) rather than intercepting an actual application call. The `repeat_count` helps compress identical consecutive events.*

Socket traces are written to text files where each line is a JSON object representing a single event. The head of such a trace typically looks like this:

```JSON
{"type": "socket", "timestamp_usec": 1773829205275013, "return_value": 9, "success": true, "thread_id": 280169, "fake_call": false, "repeat_count": 1, "details": {"sock_info": {"domain": "AF_INET", "type": "SOCK_STREAM", "protocol": "tcp", "SOCK_CLOEXEC": false, "SOCK_NONBLOCK": false}}}
{"type": "setsockopt", "timestamp_usec": 1773829205275033, "return_value": 0, "success": true, "thread_id": 280169, "fake_call": false, "repeat_count": 1, "details": {"level": "SOL_TCP", "optname": "TCP_NODELAY", "optlen": 4, "optval": true}}
```

By default, traces are saved locally in the `/tmp/tcpsnitch_output/` directory. Each execution generates a unique subdirectory stamped with the application name and the current date/time.

Inside this directory, you will find:
- **[0-N].json**: One JSON file per intercepted socket, recording the `libc` events sequentially.
- **logs.txt**: Internal logs generated by the tool.
- **meta/**: Execution metadata (kernel version, command-line arguments, environment details, etc.).
- **netlink_events.jsonl**: Records of IP/Route changes monitored during the execution.

### 🔬 eBPF Mode (Linux x86-64 Only)
If you run the tool with the **`-e`** flag (requires root/sudo), `tcpsnitch` will load an eBPF program into the kernel to track low-level TCP events (retransmissions, drops, state changes) that are invisible from userspace.

> **Note on Android eBPF:** While an `android-ebpf` target exists, its functionality is currently limited by SELinux policies on **Kernel 4.19**. The tool will automatically fallback to standard `LD_PRELOAD` tracing on these devices. However, newer Android devices running **Kernel 5.10+ (GKI - Generic Kernel Image)** should support these tracepoints.

```bash
$ sudo tcpsnitch -e curl google.com
[tcpsnitch] Trace saved in: /tmp/tcpsnitch_output/curl_20260318_112016
```

When run in this mode, an additional **`ebpf_events.jsonl`** file is generated in the output folder.

---

### Advanced Data Extraction
`tcpsnitch` also allows for granular monitoring of socket health and raw traffic:

* **TCP_INFO Polling**: You can extract the `TCP_INFO` socket option at user-defined intervals using the **`-u`** (microseconds) and **`-b`** (bytes transferred) flags.
* **Packet Capture (.pcap)**: On Linux host machines, you can record a full raw packet trace for each individual socket using the **`-c`** flag.
    * *Note: `.pcap` capture is currently disabled for Android targets.*
    * *Requirement: This feature requires root/sudo privileges to access network interfaces.*


## Compatibility

`tcpsnitch` allows tracing applications on:
- **Linux (64-bit & 32-bit):** Standard tracing requires **Kernel >= 3.2**. The eBPF tracing mode (`-e`) requires **Kernel >= 5.10** with BTF enabled.
- **Android:** Tested up to Android 14 (API 34). Requires a rooted device.

As `tcpsnitch` works by intercepting calls to `libc` functions using the `LD_PRELOAD` environment variable, tracing cannot be performed for applications which are statically linked with `libc` (e.g., modern Go binaries).

*Note: On Linux, Chrome (and any Chromium-based app such as Electron, Opera, etc.) are known to be NOT compatible as they implement their own network stack, bypassing the standard OS `libc` hooks.*

## Usage

Usage: `tcpsnitch [<options>] <cmd> [<cmd_args>]`

**Arguments:**
- `<options>` : tcpsnitch configuration flags.
- `<cmd>` : The command/binary to trace (mandatory).
- `<cmd_args>` : Arguments passed to the traced command.

**Simple example with `curl`:**
```bash
tcpsnitch curl google.com
```

### Supported Options:

- **`-a`** : Instrument and launch an application on a connected **Android** device.
- **`-b <bytes>`** : Extract `TCP_INFO` every `<bytes>` sent/received (default: **4096**).
- **`-c`** : Capture a **.pcap** trace for each socket (Linux only, requires **sudo**).
- **`-d <dir>`** : Base directory for traces (defaults to `/tmp/tcpsnitch_output`).
- **`-e`** : Activate **eBPF** capture for low-level kernel events (Linux only, requires **sudo**).
- **`-f <lvl>`** : Verbosity level of logs saved to `logs.txt` (0 to 5, default: **2**).
- **`-k <pkg>`** : Kill instrumented Android package and pull traces to the host.
- **`-l <lvl>`** : Verbosity of internal errors sent to `stderr` (0 to 5, default: **2**).
- **`-t <msec>`** : Frequency at which events are flushed to JSON files (default: **1000ms**).
- **`-u <usec>`** : Extract `TCP_INFO` every `<usec>` microseconds (default: **100000µs** on Linux).
- **`-v`** : Activate verbose mode (repeat `-vv` for more details).
- **`--version`** : Print `tcpsnitch` version.

---

## Extracting TCP_INFO

The `-b <bytes>` and `-u <usec>` flags allow `tcpsnitch` to periodically poll the `TCP_INFO` structure from the kernel. These snapshots appear as `tcp_info` events in the JSON trace with the metadata `"fake_call": true`.

- **By volume (`-b`)**: `TCP_INFO` is recorded every `<bytes>` transferred on the socket.
- **By time (`-u`)**: `TCP_INFO` is recorded every `<usec>` microseconds.

**Note:** If both options are set, a snapshot is recorded as soon as either condition is met.

### Defaults:
- **Linux**: Captured every **100ms** and every **4096 bytes** by default.
- **Android**: Time-based polling is **disabled by default (0)** to save resources, while volume-based polling remains active at **4096 bytes**.

---

## Packet Capture (.pcap)

The **`-c`** option activates raw packet capture for each intercepted socket, generating files compatible with **Wireshark**.

### How to launch:
On Linux, this feature requires root privileges to open raw network interfaces:
```bash
sudo tcpsnitch -c curl google.com
```

### Restrictions:
- **Permissions**: If run without `sudo`, the tool will skip packet capture (check `logs.txt` for `pcap_open_live` errors).
- **Android**: This feature is currently **not available** for Android targets.


## Android Usage

The usage on Android is a two-step process: launching the instrumentation and pulling the traces. 

**Important:** All options are supported on Android, except the `-c` (.pcap) option.

### Preliminary Setup (Once)
1. **Developer Mode:** Go to Settings > About Phone > Tap "Build number" 7 times.
2. **USB Debugging:** Enable it in Settings > System > Developer Options.
3. **Root Access (Mandatory):** Your device **must be rooted** (Magisk recommended). Modern Android security (SELinux and property restrictions) makes tracing impossible on non-rooted devices.
4. **Connect:** Plug the phone and verify with `adb devices`.

### Tracing an Application
1. **Start Tracing:** Provide a part of the package name (e.g., `wikipedia` for `org.wikipedia`).
   ```bash
   tcpsnitch -a wikipedia
   ```
   *The script will automatically find the full package name, set the required Android properties, push the library to `/data`, and launch the app.*

2. **Interact:** Use the application on the device as you normally would.

3. **Stop & Pull Traces:**
   ```bash
   tcpsnitch -k wikipedia
   ```
   *This kills the app, pulls the JSON traces from the app's internal data directory to your host's `/tmp/tcpsnitch_output/`, and cleans up the device.*

> **⚠️ Security Persistence:** `tcpsnitch` uses Android `wrap` properties to inject the library. These properties can sometimes persist. If you find an application is still being traced after a `-k` command, a **reboot** of the Android device is the most reliable way to clear all persistent properties.

## Compilation for Android

To trace modern Android apps (ARM64), `tcpsnitch` must be cross-compiled using the **Android Native Development Kit (NDK) r26+**.

### 1. Environment Setup
You don't need to generate a standalone toolchain anymore. Modern NDKs provide a direct LLVM/Clang compiler.

**Assumptions (based on 2026 test environment):**
- **Host:** Ubuntu 24.04 LTS
- **NDK Path:** `~/Android/Sdk/ndk/android-ndk-r26d`
- **Target:** Pixel 4a (5G), Android 14 (API 34)

Export the following variables in your terminal:
```bash
export NDK_ROOT=$HOME/Android/Sdk/ndk/android-ndk-r26d
export NDK_TC=$NDK_ROOT/toolchains/llvm/prebuilt/linux-x86_64
export CC_ANDROID=$NDK_TC/bin/aarch64-linux-android34-clang
```

### 2. Build & Auto-Dependencies
The build system is designed to be **Zero Friction**. You don't need to manually prepare third-party libraries. You can choose between the standard version and the experimental eBPF version.

**Standard Version:**
```bash
make android
sudo make install
```

**Experimental eBPF Version:**
```bash
make android-ebpf
sudo make install
```

**What happens under the hood?** The `Makefile` automatically detects if the Android dependencies (`libjansson`) are missing. If so, it will clone, cross-compile, and install them into `android_deps/` before building the `tcpsnitch` library.

**⚠️ Critical Note:** Every time you run a `make android` command, you **must** run `sudo make install` immediately after. The `tcpsnitch` host script looks for the Android library in `/usr/local/bin/tcpsnitch_deps/`. If you don't install it, the script will push an old version to the device or fail.

### 🔬 Technical Note on Android eBPF
The `android-ebpf` target compiles the eBPF loader and the kernel object (`tcpsnitch_android.bpf.o`). 
On **Android 14 (Kernel 4.19)**, while the library successfully creates BPF Maps, the final attachment (`BPF_PROG_LOAD`) will fail with `EPERM` due to SELinux restrictions on the `untrusted_app` context. The tool will automatically fallback to standard `LD_PRELOAD` tracing.

## FAQ

### How does it work?

`tcpsnitch` uses a hybrid approach to capture network data:

1.  **Userspace Interception (`LD_PRELOAD`)**: It leverages a feature of the Linux dynamic linker (`ld.so`) that allows loading custom shared libraries before the standard `libc`. By redefining functions like `connect()`, `send()`, or `recv()`, `tcpsnitch` acts as a "shim" (or proxy). It intercepts the application's request, records the arguments and timestamps in JSON, and then transparently forwards the call to the real `libc`.
2.  **Kernel Tracing (eBPF)**: When the `-e` flag is used, `tcpsnitch` loads a small program directly into the Linux kernel. This program attaches to **Tracepoints** (specific hooks in the TCP/IP stack). This allows the tool to catch events that happen deep inside the OS—such as TCP retransmissions or packet drops—which are completely invisible to the `libc` layer.

### Why do I need `sudo` / Root access?

Root privileges are required for two specific features:
- **eBPF (`-e`)**: Loading code into the kernel via the `bpf()` syscall is a privileged operation protected by `CAP_SYS_ADMIN` or `CAP_BPF`.
- **Packet Capture (`-c`)**: Opening "Raw Sockets" to capture actual network packets via `libpcap` requires `CAP_NET_RAW`.

On **Android**, root is mandatory because modern versions of the OS strictly forbid third-party apps from setting global system properties (like `wrap.com.pkg.name`) or accessing the `/data/` partition where the library is stored.

### What are these `wrong ELF class` errors?

These are harmless and can be ignored. To ensure compatibility, `tcpsnitch` may load both 32-bit and 64-bit versions of its library into the `LD_PRELOAD` environment variable. When you run a command, the dynamic linker attempts to load both; it successfully links the one matching the application's architecture and throws a "wrong ELF class" warning for the other. This does not affect the tracing process.
